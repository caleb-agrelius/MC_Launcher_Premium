# My Library Page

Lists modpacks whose files have been extracted, including ones from earlier sessions. UI code is the `Page::Library` branch in `src/main.cpp`. Saving and loading is in `src/Storage/Library.{h,cpp}`.

## Installed versions
A pack can have several versions installed at once, each with its own folders, mods, settings and worlds. `Modpack::installedVersions` lists them (`InstalledVersion`: key, version name, source version id, Minecraft version, loaders, files, ATLauncher optional mods, install folder, game folder) and `activeVersion` names the one PLAY uses. The pack's own `version`, `sourceVersionId`, `gameVersion`, `loaders`, `files` and `optionalMods` mirror the active version (`SelectInstalledVersion`).
- **Key:** `VersionKey(pack)` is the version name, else the source's version id, with anything but letters, digits, `.`, `-` and `_` replaced by `_` (`default` if empty).
- **Folders:** `PlanInstalledVersion` reuses a version's folders when it's installed again, else picks new ones side by side: install folder `installs/<pack id>@<key>/`, and game folder `instances/<pack id>@<key>/` for `.mrpack` packs or `<install folder>/minecraft/` for whole-pack installs. They're never nested inside another version's folders.
- **Adding:** a successful extraction or install plan calls `AddInstalledVersion`, which replaces the entry for the same key or adds one, makes it active, and refreshes the pack's name, icon and other details. Installing a different version doesn't touch the others.
- **Packs saved before versions:** `LoadPackLibrary` gives them one version keyed from their version, pointing at their original folders: `installs/<pack id>/`, and `instances/<pack id>/` (or `installs/<pack id>/minecraft/` when there's a `pack.json`). Nothing is moved.

## Saving
- When an extraction succeeds (Discover's one-step **Install**, or **Install files** on the Downloads page), the install worker posts to the `UiQueue`. That task records the version on `libraryPacks` (a `Library`, keyed by pack id) and writes `library.json` with `SavePackLibrary`. Failed or cancelled extractions aren't added.
- At startup, `LoadPackLibrary` reads `library.json` from the data folder. Versions whose install folder no longer exists are dropped, and packs left without versions are removed; the file is rewritten on the next change. A missing or corrupt file gives an empty library.
- `library.json` stores each pack's id, name, description, version, author, game version, loaders, icon URL, color, website URL, source key and source ids, the ATLauncher optional mods chosen at install (`optionalMods`), files (name, URL, size), and `installedVersions` with `activeVersion`. Files written before sources existed only have `fromModrinth`, which loads as the Modrinth source.
- On shutdown, the app drains the `UiQueue` after joining workers, so an extraction that finishes while closing is still saved.
- Each pack card shows its icon, its name, and a line with its source, version, Minecraft version and loaders (when known). With more than one version installed, the version is a dropdown of the installed versions (each with its Minecraft version) instead; picking one makes it active and saves the library, and it's disabled while the pack is being played or prepared. PLAY, Open folder and everything in Manage act on the active version. Other versions are installed from Discover. Below that is the play status: "Ready to play", the current preparation step with a spinner, "Minecraft is running", or the last error in red.
- Whole-pack installs add the pack when `RunInstallPlan` succeeds (see [pack-sources.md](pack-sources.md)).
- The card's actions sit together on the right (`AlignRightForButtons`): **Open folder**, **Manage** and **PLAY** when idle, **Cancel** while the pack is being prepared or repaired (with a thin progress bar when the step's progress is known), and **Stop game** while Minecraft runs. **PLAY** works for every source (see [launching.md](launching.md)). It uses the pack's own launch settings if it has them, else Settings > Minecraft, plus Settings > Game options (see [settings.md](settings.md)).
- **Open folder** opens the active version's game folder in Explorer.
- If no packs are installed, the page shows an empty state with a **Browse modpacks** button that opens Discover.
- **Manage** opens a menu:
  - **Open latest log** opens `<game folder>/logs/latest.log` in its default program (`Platform::OpenFile`). It's disabled until the game has written one. **Open logs folder** opens `<game folder>/logs/`.
  - **Launch settings...** (checked when the pack has its own) opens a dialog with a **Use custom launch settings** toggle. Turning it on copies Settings > Minecraft into `settings.packLaunch[<pack id>]` and shows the same Memory, Java and Game window cards for this pack only (`DrawPackLaunchSettings`). "When the game starts" stays launcher-wide.
  - **Update...** (every source but the local index) opens the update dialog (see "Updating a pack" below).
  - **Repair files** (`startRepair`): for `.mrpack` packs, `RepairModpack()` checks every file the pack lists against its SHA-1, deletes damaged ones and downloads what's missing ("Checking files (n/total)", then "Downloading mods"). The player's configs and worlds are kept. Whole-pack installs re-run their install plan, which keeps files whose hash still matches and re-fetches the rest, with progress on the Downloads page. A toast reports the result.
  - **Uninstall...** (one version installed), or **Uninstall <version>...** and **Uninstall all versions...** (several), asks for confirmation listing the game folders that go, and is disabled while the pack is being played, prepared, downloaded, installed or updated. `uninstallPack(pack, versionKey)`:
    - One version: removes it from the pack (the newest remaining one becomes active if it was), drops that version's saved downloads, and deletes its install and game folders (worlds included). Removing the last version removes the pack.
    - All versions: removes the pack, its saved downloads and its per-pack launch settings, and deletes every version's folders and `downloads/<pack id>/`.
    - Folders come from `library.json`, so only ones directly under `installs/` or `instances/` named `<pack id>` or `<pack id>@...` are deleted; others are logged and skipped. Deleting runs on a worker. Deleting uses `\\?\` paths so deeply nested files go too. A pack id that isn't a single plain folder name is refused.
    - When the uninstall removes the whole pack and it has a server folder, the dialog offers **Also delete its server** (off by default; disabled while the server runs or is being set up). Otherwise the server is kept and stays on the Servers page. Uninstalling one of several versions never touches the server.
- Pack cards show the pack's summary under the version line, shortened to 160 characters at a word boundary (`ShortenText`).
- Pack cards also offer **Server** when the active version's files can be hosted (`CanCreateServer` on its install folder), which opens the pack on [Servers](servers.md) for dedicated hosting.
- Cards share measured heights, padding, 56px icons and heading-size pack names with Downloads; long text wraps, and actions move to a new row when necessary.
- Packs extracted before `library.json` existed aren't detected from `installs/` alone. Install them again to list them.

## Updating a pack
**Manage > Update...** moves a pack to its source's newest version and keeps the player's worlds and options. The state lives in `main.cpp` (`updateCheck`, `packUpdates`, `startUpdateCheck`, `startUpdate`, `onVersionInstalled`). The copying is `CarryOverPlayerData` in `src/Game/PackInstance.{h,cpp}`.
- **Check:** opening the dialog calls `FetchPackVersion` on a worker (the version Discover installs by default) and applies it to a copy of the library pack with `ApplyPackVersion`. ATLauncher packs keep their optional mod choices. The dialog says when the active version is already the newest, or when the newest is installed but not active (pick it in the version dropdown). A failed check shows the error with **Try again**.
- **Confirm:** the dialog names both versions, warns in red when the Minecraft version changes, and has **Remove <old version> afterwards** (off by default). **Update** is disabled while the game runs or is being prepared, and while the pack has a download or install going.
- **Install:** the new version installs side by side like any other version (see "Installed versions"): `startPlanInstall` for whole-pack sources, and for Modrinth `startDownloadInstall` with the version's `.mrpack` (the same download-then-extract step as Discover's **Install**). Progress is on the Downloads page. Meanwhile the card shows "Updating to <version>" with a spinner, and **PLAY**, **Manage** and the version dropdown are disabled.
- **Carry over:** when the install succeeds and the new version is active, `onVersionInstalled` copies `PlayerDataPaths()` from the old version's game folder to the new one's on a worker: `saves/`, `screenshots/`, `resourcepacks/`, `shaderpacks/`, `schematics/`, `servers.dat`, `options.txt`, `optionsof.txt` and `optionsshaders.txt`. Mods and configs aren't copied, because the new version brings its own. Files that already exist in the new folder are kept, so the new version's own files win. For `.mrpack` packs the game folder is only filled on the first PLAY, and the pack's overrides are copied over whatever is there, so the same rule holds. Copying uses `\\?\` paths, so deeply nested world files work.
- **Finish:** a toast reports the result. With **Remove** checked, the old version is then uninstalled with `uninstallPack` (its folders, worlds included, are deleted), unless the game was started in the meantime; then it's kept and the toast says so. If copying fails, the new version stays installed and active, the old one is always kept, and the toast gives the error. A failed install leaves the library as it was.
